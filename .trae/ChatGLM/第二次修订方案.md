# 密码修改 + 多文件上传 + 首页批次卡片 —— 方案总结

> 技术栈：Node + Express 4 + better-sqlite3 + 原生 JS 前端（无框架、无构建）。
> 执行原则：严格照方案做，不顺手重构；未提到的文件不改；不新增 npm 依赖；注释中文；CSS 追加到 style.css 末尾且只用现有 design tokens；用户数据插入 DOM 必须 escapeHtml/escapeAttribute。

---

## 一、功能一：密码修改（邮箱验证链接）

### 流程
- 两个入口共用一套"链接令牌"流程：
  - 入口 A：已登录用户在 dashboard「账号安全」点「修改密码」→ 系统向注册邮箱发链接。
  - 入口 B：未登录用户在 login 页点「忘记密码」→ 输入注册邮箱 → 发链接。
  - 都落到 `reset-password.html?token=xxx` 设置新密码。
- 成功后再发一封"密码已更新"通知邮件。

### 关键实现
| 文件 | 改动 |
|---|---|
| database.js | 新建 `password_reset_tokens` 表（仅存令牌 SHA-256 哈希，单次使用，30 分钟过期） |
| config.js / .env.example | 新增 `JINCHAO_BASE_URL`（邮件链接地址，留空回退请求 Host） |
| email.js | 新增 `sendPasswordResetEmail`、`sendPasswordChangedEmail` |
| server.js | 辅助函数：generateResetToken / hashResetToken / siteBaseUrl / findValidResetToken / maskEmail；三个接口：`POST /api/password-reset/request`、`GET /api/password-reset/verify`、`POST /api/password-reset/confirm`；限流纳入新接口 |
| 前端 | 新页面 `forgot-password.html`（忘记密码）、`reset-password.html`（重置页，状态机：校验中→失败隐藏表单→成功显示表单+脱敏邮箱）；app.js 新增 handleForgotPassword / requestPasswordReset / initResetPasswordPage / handleConfirmResetPassword |
| login.html / dashboard.html | 分别加「忘记密码」「修改密码」入口与消息容器 |

### 安全要点
- 令牌只存哈希、单次使用、重复申请使旧链接失效；邮件发送失败回收令牌。
- 重置成功后：撤销该用户所有登录会话（`user_sessions.revoked = 1`）、清除登录失败锁定。
- 密码至少 8 位；前端校验两次输入一致（不发请求）。
- 死代码（sendResetCode / handleResetPassword 及验证码式重置接口）保留不改。

## 二、功能二：多文件上传

### 流程
- dashboard「文件」面板升级：一次多选（最多 20 个）、批次统一标题/密码、总体进度条 + 每文件状态队列、格式错误清单、部分成功语义（合法入库，非法跳过并列原因）。
- 图片：前端 Canvas 生成 200×200 缩略图（contain 保持比例，JPEG 0.85），九宫格展示，点击灯箱看原图。
- 音频：自定义播放器（播放/暂停、进度拖动、音量）。
- 其他文件：列表展示。

### 关键实现
| 文件 | 改动 |
|---|---|
| database.js | files 表新增 `thumbnail` 字段 |
| validation.js | 扩展名白名单（图片/音频/视频/文档压缩包）+ 危险扩展名黑名单（.exe 等）+ `validateUploadFile` |
| server.js | 新增 thumbnails 目录；`fileUpload.fields` 支持 files + thumbnails 两字段，fileFilter 校验格式（不合法记入 rejectedFiles 跳过）；上传路由整批插入事务化；新增 `GET /api/files/:id/raw` 内联返回原文件（供 img/audio 使用）；`GET /api/files` 补充 thumbnailUrl / rawUrl 字段 |
| 前端 | 队列渲染 handleFileSelectionChange、缩略图 generateThumbnail、XHR 整批上传 uploadFileBatch（fetch 不支持上传进度）、结果渲染 renderUploadResult / fileGalleryMarkup / audioPlayerMarkup / setupAudioPlayers、灯箱 openFileLightbox / closeFileLightbox、文件库 loadFileGallery |
| dashboard.html | 重写 #panel-file（表单 + 进度条 + 队列 + 错误清单 + 结果区 + 文件库 + 灯箱 DOM） |

### 前后端关键约定
- `thumbnailIndexes`（形如 "0,3,5"）对齐"第几个文件带缩略图"——改前端 append 顺序必须同步改此字段，最易出错点。
- 缩略图必须 `object-fit: contain`（不得用 cover）。
- 一个 XHR 传整批，不为每个文件单独发请求。

## 三、第四部分：首页文件批次卡片与详情页

### 核心语义
**一次上传 = 一个批次（batch_id）= 首页一张卡片。**

### 展示规则
| 批次内容 | 首页卡片展示 | 溢出处理 | 点击行为 |
|---|---|---|---|
| 图片 | 九宫格最多 9 张 | 第 9 张模糊 + 显示 `+x`（x = 总数 - 9） | 点溢出格跳详情页；前 8 张仍开灯箱看原图 |
| 音频 | 最多 3 个播放器（可在线播放） | 第 3 个模糊 + `+x`（x = 总数 - 3） | 点溢出卡片跳详情页；普通卡片可播放不跳转 |
| 其他文件 | 只显示"📁 共 N 个文件"卡片 | 无 | 点卡片跳详情页 |

### 关键实现
| 文件 | 改动 |
|---|---|
| database.js | files 表新增 `batch_id`、`batch_index` 字段（历史数据不回填，聚合时旧文件视为独立批次） |
| server.js | 上传路由生成 batchId 并随 INSERT 写入；新增 `GET /api/file-batches` 聚合接口（按批次分组返回 images / audios / others 列表） |
| 前端 | 新页面 `file-detail.html`（详情页展示该批次全部图片+灯箱、全部音频播放器、其他文件下载列表）；app.js 新增 renderFileBatches（首页卡片渲染）、跳转事件委托、initFileDetailPage |
| index.html | 文件列表区加 `#file-batch-list` 容器，初始化时调 `renderFileBatches()` |
| style.css | 批次卡片、溢出模糊（filter: blur(4px) + pointer-events: none）+ 覆盖式 +x 徽标、其他文件卡片、详情页样式 |

### 事件委托冲突处理（重要）
6.9.7 已有灯箱委托会把溢出格也弹灯箱。解决：在 6.9.7 委托回调开头加
`if (event.target.closest('.file-gallery-item.is-overflow')) return;`
溢出格由跳转委托接管，非溢出格仍走灯箱。

## 四、禁止事项（全文通用）

1. 不删除/修改：app.js 死代码、验证码式重置接口、videoUpload/avatarUpload、download 路由、已有测试用例。
2. 不新增 npm 依赖、不改 package.json、不引入构建工具。
3. 缩略图只用前端 Canvas 生成；不得用 object-fit: cover。
4. 整批一个 XHR 上传，不为每个文件单独发请求。
5. 不改 public/uploads/ 已有目录结构，只新增 thumbnails。
6. 邮件 HTML 用字符串拼接，不用外链图片或模板引擎。

## 五、验证清单（冒烟）

1. `npm test` 全绿（含新增 validateUploadFile 用例）。
2. `node server.js` 启动后：forgot-password.html / reset-password.html 返回 200；未带 token 的 verify 返回"缺少验证令牌"。
3. 密码修改端到端：入口 A/B → 收邮件 → 设新密码 → 收通知邮件 → 新密码可登录、旧密码失败、其他会话被踢出、链接单次使用。
4. 多文件上传：混合选图/音频/.exe → 队列状态与错误清单正确 → 进度条实时 → 结果区九宫格/播放器正常 → 文件库刷新。
5. 批次卡片：上传 12 张图 → 首页一张卡片显示 9 张，第 9 张模糊 +3，点击跳详情页显示全部；上传 5 个音频 → 卡片显示 3 个播放器（前 2 个可播），第 3 个模糊 +2，点击跳详情页全部可播；上传 PDF/ZIP → "共 N 个文件"卡片，点击跳详情页可下载。
6. 浏览器控制台无 JS 报错。

## 六、已知风险

- 邮件发送依赖 .env 正确配置 QQ SMTP 授权码，未配置则提示"发送验证邮件失败"。
- .env 的 JINCHAO_SESSION_SECRET 当前疑似是命令文本，建议先修正。
- thumbnailIndexes 前后端对齐是最易错点。
- 缩略图由客户端产出，理论上可被绕过（仅影响展示，不影响安全）。
- 音频能否播放取决于浏览器对格式的支持（mp3/wav/ogg 通常无问题）。
- 本方案不实现：密码强度提示、断点续传、视频播放器、服务端缩略图回退。
